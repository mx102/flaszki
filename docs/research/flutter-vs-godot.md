# Research: Flutter vs Godot 4 for Flaszki

Issue: [#2](https://github.com/mx102/flaszki/issues/2). Map: [#1](https://github.com/mx102/flaszki/issues/1). Decision lives in [#4](https://github.com/mx102/flaszki/issues/4).

Facts only, no recommendation. Researched 2026-11-14 against **Flutter 3.50** docs and **Godot 4.7 (stable)** docs. Source of each claim is linked; items marked *(secondary)* or *(measured)* are not from official docs.

## 1. Platform support maturity

### Flutter
- Supported (3.50): Android API 24–37; iOS 15–27; Windows 10/11; macOS 12–27; Chrome/Edge latest 2, Firefox latest 2, Safari 15.6+ [F2].
  - Note: iOS deploy page still says "Flutter supports iOS 13 and later" [F8] — conflicts with supported-platforms table (15+) [F2].
- Web renderers: CanvasKit and Skwasm, via WebGL/WebGPU [F3]. HTML renderer not mentioned in current docs [F3].
- Wasm builds need WasmGC + JS String Builtins + exnref: Chromium 137+, Safari 26.2+, Firefox 147+. In 3.50, Wasm is used by default only on Chromium; Safari/iOS and Firefox fall back to dart2js + CanvasKit unless opted in via `wasmAllowList` [F4].
- `--wasm` build always also emits JS fallback [F4].
- Multithreaded Wasm rendering needs COOP/COEP headers [F4].
- Web not suited for SEO/static content; fine for app-like/PWA [F9]. No caching service worker generated by default any more [F9].

### Godot
- Exports: Windows, macOS, Linux/BSD, Android, iOS, Web [G2].
- Web: needs WebAssembly + WebGL 2.0; Compatibility renderer only (no Forward+/Mobile, no WebGPU) [G3].
- Web: single-threaded export is default since 4.3; works better on macOS/iOS and on itch.io-style hosts; lower perf than threaded [G3]. Threaded export / GDExtension on web need COOP/COEP (or PWA service-worker workaround) [G3].
- "Safari has several issues with WebGL 2.0 support that other browsers don't have." Chromium/Firefox recommended [G3].
- Apple devices "were long known to have issues" with Godot web exports; single-threaded export makes them "disappear"; known Safari page reloads on memory use in one demo [G4].
- Mobile web: "CPU and GPU resources are tight", Wasm slower than native [G3].
- Web audio: Sample mode default (low latency, no effects); Stream mode adds latency without threads [G3].
- Web `user://` persistence uses IndexedDB; lost in incognito [G3]. (Relevant to Local-only progress save.)
- iOS export: needs macOS + Xcode; Godot generates an Xcode project, build/upload via Xcode [G6]. iOS simulator: Compatibility renderer only [G6].

## 2. Web export size / perf

- **Flutter**: official docs give no web size figures [F10][F9]. Measured on stable engine `371f772…` from gstatic CDN *(measured, 2026-11-14)*: `canvaskit.wasm` 7,315,452 B (2,925,340 B gzip -9); `skwasm.wasm` 3,612,036 B (1,543,904 B gzip -9). App's compiled Dart (`main.dart.js` / `.wasm`) comes on top, not measured.
- **Godot**: 4.3 web `.wasm` "around 40 MB uncompressed, and 5 MB compressed with Brotli" [G4]. Docs: gzip shrinks `.wasm` to ~¼; custom template with unused features disabled shrinks it further [G3]. Community reports 20–40 MB raw / 4–9 MB compressed *(secondary)* [S1][S2]. Asset `.pck` extra.

## 3. 2D animation of fluid Pours

### Flutter
- Custom drawing via `CustomPainter`/`Canvas` + `AnimationController` [F11].
- Fragment shaders (GLSL `.frag`, versions 100–460) on Skia and Impeller; no vertex shaders, no UBO/SSBO, only `sampler2D`, no bool/uint uniforms [F12]. Shader loading can be expensive on Skia — precache before animating [F12]. Docs don't state web renderer support for fragment shaders [F12].

### Godot
- Built-in 2D nodes (Polygon2D, Line2D, Path2D), `Tween`, `AnimationPlayer`, CanvasItem shaders [G11].
- Compatibility renderer (forced on web) has no 2D MSAA; Line2D has own `antialiased` flag, Polygon2D has none [G12].

## 4. Open-source licensing

- Flutter: BSD 3-Clause, "Copyright 2014 The Flutter Authors" [F1]. Dart SDK also BSD-3 [F13].
- Godot: MIT; only redistribution requirement is the copyright + license notice, credits link acceptable; third-party components listed in COPYRIGHT.txt, all MIT-compatible; game content owned by author, any license [G1].
- Both permissive → compatible with any OSI license chosen for Flaszki (GPL, MIT, Apache…). Third-party packages/plugins must be checked individually.

## 5. CPU perf for on-device generator/solver

Constraint (from #1): Level N generated in < ~200 ms on a low-end phone.

### Flutter / Dart
- Mobile/desktop: Dart compiled AOT to native ARM/x64 [F3].
- Web: dart2js or dart2wasm [F3].
- Background work: `Isolate.run` / `compute()` on mobile/desktop. **Web has no isolates; `compute()` runs on main thread** [F5] → generator would block UI on web unless sliced or a Web Worker is used.

### Godot
- FAQ: "the performance of C# and GDScript is within the same order of magnitude, and C++ is faster than both"; C++ via GDExtension "will almost always be faster" [G2].
- GDScript static typing "improves performance by using optimized opcodes"; further optimizations (JIT/AOT) planned, not shipped [G13]. Dynamic typing: "Less performance than statically typed languages" [G14].
- C#: Android + iOS experimental; **web not supported** in Godot 4 [G5][G3].
- GDExtension on web: needs "Extensions Support" + cross-origin isolation headers, compiled for web [G3].
- Threads on web only with Thread Support (COOP/COEP); default export is single-threaded [G3].

No official benchmark found comparing Dart vs GDScript; must be measured with a generator prototype.

## 6. Testability of pure game logic

### Flutter
- Unit tests test a single function/class; "generally don't read from or write to disk, render to screen…"; widget tests use a test environment; only integration tests need device/emulator [F6]. Pure Dart logic (Pour rules, generator, solver) testable headless with `flutter test`/`dart test`.

### Godot
- No built-in GDScript unit-test framework; engine's `--test` runs only when engine compiled with `tests=yes` (engine C++ tests) [G10].
- Headless: `--headless`, `-s/--script` for CI [G10].
- Third-party: **GUT** (MIT, GUT 9.7.x supports Godot 4.7, CLI) [G8]; **gdUnit4** (MIT, GDScript + C#, CLI for CI, JUnit XML, GitHub Action) [G9].

## 7. Store publishing tooling

### Flutter
- Android: `flutter build appbundle`; iOS: `flutter build ipa` → `.xcarchive` + `.ipa`; upload via Transporter, `xcrun altool`, or Xcode [F7][F8].
- Documented CI/CD: fastlane (Play `upload_to_play_store`, `upload_to_testflight`), Codemagic, Bitrise, Appcircle, Xcode Cloud [F7].
- iOS/macOS builds need macOS + Xcode; App Store needs Apple Developer Program [F8].

### Godot
- Android: JDK 17, Android SDK 35, NDK r28b; AAB requires Gradle build; release keystore in export preset [G7].
- iOS: export → Xcode project → archive/upload in Xcode; needs Team ID + bundle ID [G6].
- macOS: signing + notarization from macOS (Xcode notarytool) or from Linux/Windows via `rcodesign`; App Store needs App Sandbox [G15].
- CLI `--export-release <preset> <path>` "especially useful for continuous integration" [G10]. No first-party fastlane-style upload tooling documented; upload steps are platform tools.

## Open questions (need prototype/measurement)

- Real generator+solver time per Level on low-end Android: Dart AOT vs typed GDScript.
- Total first-load web size for a minimal Flaszki build in each.
- Whether Flutter's web main-thread generation stays < 200 ms (no isolates on web).
- Safari/iOS web smoothness of Pour animation in each.
